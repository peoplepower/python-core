Concepts in this bundle describe things that live **outside** it — source repositories, external
services, documents. Nothing inside the bundle changes when those do, so freshness has to come
from process. Three mechanisms work together, in order of value:

1. **Point-of-change updates** — source repos carry a `CLAUDE.md` note pointing back here, so a session that changes documented behavior also updates the concept.
2. **Freshness contracts** — concepts declare what they were verified against (`sources`) and the date after which they should not be trusted unreviewed (`stale_after`), making staleness mechanically detectable.
3. **A periodic review sweep** — score every concept and flag the ones needing re-verification in [log.md](/log.md).

# The freshness contract

Two optional frontmatter families on any concept:

```yaml
stale_after: 2027-03-08T00:00:00Z    # absolute; no stale_after implies a 365-day default shelf life
sources:
  - id: order-service
    resource: example-org/order-service:src/orders
    title: Order service implementation
    last_modified: 2026-08-30T00:00:00Z
```

`resource` may be an absolute URL, a bundle-relative path starting with `/`, a relative path, or the
repo-slug form `<org>/<repo>:<path-within-repo>`. The slug names a repo by the org/repo tail of its git
remote (so `example-org/order-service:src/...` ↔ `https://github.com/example-org/order-service/tree/main/src/...`),
which keeps the reference valid on any machine. The path part may be a directory, a file, or a glob
(`*`, `?`, `[...]`); omit `:path` to reference the whole repo.

Locally, `okf.py freshness` resolves slugs by scanning `--repos-root` (default: the bundle's parent
directory) for git checkouts and matching each checkout's `origin` remote — no per-machine
configuration. A repo not checked out locally makes its sources **unverifiable** (the concept is scored
on shelf life alone and noted as such); a path missing inside a *present* checkout counts as **drift**.

## Choosing stale_after

Set it by volatility, measured from the date you are writing:

| Horizon | Suits |
|---|---|
| ~90 days | Fast-moving product surfaces; figures that move monthly |
| ~180 days | Vendor integrations; measured operational inputs |
| ~365 days | Architecture overviews; goals, decisions, and settled arithmetic |

`stale_after` is **absolute**, not a relative TTL, so a copied or forked document cannot silently change
meaning, and a reader without the tooling can still tell whether a concept has expired. [^spec]

# The scorer

```sh
python3 tools/okf.py freshness                   # list sub-fresh concepts
python3 tools/okf.py freshness --all             # list everything
python3 tools/okf.py freshness --json            # machine-readable, for agents
python3 tools/okf.py freshness --fail-under 35   # exit 1 if anything is stale
```

Each concept gets a 0–100 score. [^dosu]

| Penalty | Trigger | Formula | Cap |
|---|---|---|---|
| Age delta | a declared source changed after the concept was last touched | `(doc_age_days − source_age_days) / 3` | 30 |
| Shelf expiry | concept untouched past `stale_after` | `days_past × 2` | 30 |
| Source drift | a declared source path no longer exists | `10 × missing paths` | 40 |

Bands: **fresh** ≥ 65 > **review** ≥ 35 > **stale**. A concept past its `stale_after` is stale by
definition and is banded stale regardless of score.

The concept's own age comes from the bundle's git history, falling back to `generated.at`, then the
legacy `timestamp`, then file mtime. Source recency comes from each source's `last_modified` and, for
path-valued resources present locally, that file's own git or mtime age.

Concepts with no `sources` are scored on shelf life alone — **declaring sources is what makes drift
visible**, so add them whenever you touch a concept that documents something external.

The same scores appear in the Health pane of `okf-viz.html` (regenerated by `okf.py viz`).

# Point-of-change updates

Documented source repos carry a short section in their `CLAUDE.md`: when a change alters behavior this
bundle documents, update the matching concept, bump its `generated.at`, add a [log.md](/log.md) entry,
and re-run `okf.py index` + `validate`. To find the concepts documenting a repo, grep the bundle for the
repo name or path.

# The periodic sweep

Run `python3 tools/okf.py freshness` periodically. When concepts land in the `review` or `stale` bands:

1. Re-read each one against its `sources`.
2. Flag what appears outdated as a dated **Freshness review** entry in [log.md](/log.md) — **flag, don't silently rewrite**.
3. Update the concepts that are genuinely wrong, bumping `generated.at` and adding a `**Correction**:` log entry explaining what changed and why.

Step 2 matters more than it looks. A concept that is quietly rewritten loses the record of having been
wrong, and that record is what tells a future reader — human or agent — how much to trust the rest.
